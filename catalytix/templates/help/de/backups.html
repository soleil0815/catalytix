Unter Administration → Datensicherung wird die Datenbank {% if f.backup_enabled %}jeden Tag automatisch ab {{ "%02d"|format(f.backup_hour) }}:00 Uhr gesichert{% else %}derzeit nicht automatisch gesichert – schalte Täglich automatisch sichern ein{% endif %}. Das läuft im laufenden Betrieb, jede Sicherung wird auf Beschädigung geprüft. Aufbewahrt werden {{ "die neueste" if f.backup_keep == 1 else "die neuesten" }} {{ f.backup_keep }} (einstellbar 1–100), ältere werden gelöscht.

  • Jetzt sichern legt sofort eine Sicherung an – sinnvoll vor größeren Änderungen oder einem Update.
  • Jede Sicherung lässt sich herunterladen oder löschen. Ablage: ./data/backups oder der Ordner aus CATALYTIX_BACKUP_DIR (z. B. ein NAS).
  • Schlägt eine Sicherung fehl, erscheint ein Warnzeichen am Menüpunkt und Administratoren bekommen eine E-Mail{% if not f.mail_on %} (sobald der E-Mail-Versand aktiv ist){% endif %}.
  • Gesichert wird die Datenbank. Cover, Logo und secret_key liegen als Dateien in ./data – für einen Umzug den ganzen Ordner mitnehmen. Eine Datenbank immer zusammen mit ihrer secret_key zurückspielen: Ohne den passenden Schlüssel funktionieren 2FA-Anmeldungen und gespeicherte SMTP-/AD-Passwörter nicht, und Catalytix startet nicht.

Wichtig: Die Sicherungen liegen auf demselben Server und schützen nicht vor einem Festplattenausfall. Kopiert den Ordner regelmäßig an einen anderen Ort.

Wiederherstellen (auf dem Server; der aktuelle Stand wird vorher automatisch gesichert):

docker compose stop catalytix
docker compose run --rm catalytix flask --app wsgi list-backups
docker compose run --rm catalytix flask --app wsgi restore-backup DATEINAME.db
docker compose start catalytix

Alles, was nach der Sicherung passiert ist, geht dabei verloren.
