Whether readers may create their own accounts is set under Settings → Self-registration. Currently: {% if f.registration_mode == "approval" %}allowed – administrator approval required{% elif f.registration_mode == "open" %}allowed – account active immediately{% else %}off{% endif %}.

  • off – no link on the sign-in page; the registration page does not exist.
  • allowed – approval by an administrator required – the account is created disabled. Approve or reject it under Users (filter Awaiting approval). A counter in the sidebar shows pending registrations.
  • allowed – account active immediately – the account can be used straight away.

Options:

  • Require email confirmation – link by email, valid for 48 hours.{% if f.registration_verify and not f.mail_on %} Note: email delivery is not active, so confirmation is currently not enforced.{% endif %}
  • Notify administrators of new registrations by email about every new registration.
  • Only allow these email domains, e.g. school.org (subdomains included).
  • Group for new readers – otherwise they only see general books.
  • If a privacy policy is set under Legal, it must be accepted when registering.{% if not f.privacy_set %} None is set at the moment.{% endif %}

New accounts are always readers. Built-in protection: bot trap, minimum form-filling time, at most 5 registrations per hour and IP address, reserved names, Active Directory usernames blocked, password at least 10 characters. Unconfirmed accounts are deleted automatically after 7 days.
