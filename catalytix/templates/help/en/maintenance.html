Updates and emergency commands run on the server, in the folder containing docker-compose.yml. Your own values (port, time zone …) live in .env; updates never overwrite it, nor ./data or docker-compose.override.yml.

The program is completely inside the image ghcr.io/soleil0815/catalytix. The server only holds docker-compose.yml, .env and ./data (plus, optionally, update.sh).

Updating: with a container manager (Dockhand, Watchtower …) – preferably at night – or by hand with docker compose pull && docker compose up -d. Or with update.sh:

./update.sh                        # newest version (or the one fixed in .env)
./update.sh --version=X.Y.Z        # exactly this version (also a security update X.Y.Z-s2)
./update.sh --version=latest       # follow every new version again
./update.sh --load FILE.tar.gz     # without internet: image file from the release
./update.sh --cleanup              # installations from before 3.0.0: remove old program files

update.sh keeps the running image as previous, gets the new one, starts it and waits for the health check. If the new version does not start, it restores the backup from before the update and starts the previous version again (asks first, automatic with -y). If the image brings a newer docker-compose.yml, it puts it in place and keeps the old one as docker-compose.yml.alt.

At every version change the program backs up the database itself at start-up (Backup: "before update to X.Y.Z") before changing it. An older version does not start on a database a newer one has already used – the log then names the backup to restore. Going back to an older version: ./update.sh --version=X.Y.Z (restores the matching backup; everything entered since is lost). Fixing a version: CATALYTIX_TAG=X.Y.Z in .env.

If the Overview says the docker-compose.yml is outdated: run ./update.sh once, or replace the file with the one from the release and run docker compose up -d.

Pinned versions and security updates: base image (with digest), operating system packages and all Python packages (with hashes) are pinned to exact versions – every build gives the same image. On GitHub these versions are renewed automatically once a month on patch day (the second Tuesday), but only within the foundation (Debian 13, Python 3.13, every package within its major version). The new image is built without cache, tested in the finished image and scanned for vulnerabilities; only if everything passes is it published as latest and as <version>-s<counter> (same program, only new packages), with a CHANGELOG entry. If the server follows latest (the default), a container manager, docker compose pull or ./update.sh picks up these security updates. In addition, the published image is scanned daily, and weekly it is checked how long Debian and Python still get security updates.

If a run on GitHub turns red (GitHub then sends an email): nothing was published, the server keeps running unchanged. The cause is shown at the top of the run. Usually a fix is not 7 days old yet – then wait for the next patch day or start Actions → Security update → Run workflow with cooldown_days = 0. Failed tests, vulnerabilities without a fix inside the foundation or a foundation warning need a deliberate change; the README describes each case.

Emergency commands – each prefixed with docker compose exec catalytix docker-entrypoint.sh (going through the entrypoint runs them without root rights like the app, so e.g. backups are not owned by root):

  • flask --app wsgi reset-password admin – new password for a local account (also re-enables it)
  • flask --app wsgi reset-2fa admin – reset the second factor
  • flask --app wsgi create-admin emergency – additional local admin account
  • flask --app wsgi backup / list-backups – back up now / list backups
  • flask --app wsgi restore-for-version X.Y.Z – restore the backup for going back to X.Y.Z (stop the server first; prefix with docker compose run --rm -e CATALYTIX_SKIP_DB_CHECK=1 catalytix)
  • flask --app wsgi send-reminders – send reminders now
  • flask --app wsgi apply-retention – apply the retention period now

Most of this is also available in the interface: reset 2FA and lift sign-in locks in the user's account, Back up now, Send now, Clean up now. The version is shown at the bottom of the sidebar; clicking it shows the licence and source code.
